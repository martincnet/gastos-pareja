Guía rápida

Chuletas para seguir aprendiendo

Esta guía junta dos referencias pensadas para usar mientras trabajás en el proyecto: una chuleta básica de comandos y flujo diario, y otra enfocada en Git para no romper nada.

1. Chuleta Básica

Comandos que vas a usar seguido

cd /Users/martin/gastos-pareja

Entrar al proyecto.

git status

Ver qué cambió.

git branch --show-current

Ver en qué rama estás.

npm run dev

Levantar la app local.

npm run build

Ver si compila bien.

git add archivo
git commit -m "mensaje"

Guardar cambios en Git.

git push

Subir cambios a GitHub.

firebase deploy --only hosting

Publicar frontend.

Flujo seguro para trabajar sin miedo

  1. Antes de empezar: 
    git checkout main
git pull
git checkout -b nombre-de-tu-rama
  2. Mientras trabajás: 
    npm run dev

    Y cada tanto:

    git status
npm run build
  3. Cuando terminaste: 
    git add src/App.jsx
git commit -m "feat: mejora historial"
git push -u origin mejora-historial
  4. Cuando ya probaste todo: 
    git checkout main
git pull
git merge mejora-historial
git push

Cómo deployar sin romper nada

  1. Estar en main
  2. Tener todo commiteado
  3. Hacer npm run build
  4. Si compila bien, deployar
git checkout main
git status
npm run build
firebase deploy --only hosting

Cómo revisar si algo está raro

git status

Te dice si tenés cambios sin guardar.

git log --oneline -n 5

Te muestra los últimos commits.

git diff

Te muestra qué cambió todavía no commiteado.

Cuándo usar rama nueva

  • Si vas a tocar UI importante.
  • Si no estás seguro del resultado.
  • Si querés probar ideas.
  • Si el cambio puede romper algo.

Qué hacer si ves la versión vieja en el navegador

  1. Abrí localhost en navegador normal.
  2. Hacé hard refresh.
  3. Si sigue igual, limpiá cache o service worker.
  4. Confirmá que estés en la rama correcta.
git branch --show-current
Regla mental simple:
dev = probar local
build = validar que no rompiste
commit = guardar avance
push = subirlo
deploy = publicarlo

2. Git para no romper nada

Comandos amigos

git status
git branch --show-current
git log --oneline -n 5
git diff

Con esos cuatro ya podés entender casi cualquier situación básica.

Regla de oro

Antes de tocar algo raro en Git, primero mirá el estado. No hagas comandos destructivos si no entendés exactamente qué van a hacer.

Error común: no sé en qué rama estoy

git branch --show-current

Si querés cambiar de rama:

git checkout main

Error común: tengo cambios y no sé si los guardé

git status

Si aparecen archivos en rojo o verde, todavía no está todo guardado en commit.

Error común: no entiendo qué cambió

git diff

Eso te muestra la diferencia exacta en los archivos todavía no commiteados.

Error común: quiero guardar mi avance sin complicarme

git add src/App.jsx
git commit -m "fix: corrige bug en formulario de gasto"

Error común: quiero probar algo sin tocar main

git checkout main
git pull
git checkout -b prueba-nueva-ui

Error común: quiero volver a la rama principal

git checkout main

Error común: terminé una rama y la quiero unir

git checkout main
git pull
git merge nombre-de-tu-rama
git push

Error común: hice merge y quiero limpiar la rama

git branch -d nombre-de-tu-rama

Si también querés borrar la rama remota:

git push origin --delete nombre-de-tu-rama

Qué hacer si te equivocaste

  • Si todavía no hiciste commit: usá git status y git diff.
  • Si ya hiciste commit pero no pusheaste: frená y revisá antes de tocar nada fuerte.
  • Si no entendés lo que ves: pedí ayuda antes de usar comandos destructivos.
Consejo práctico:
Si no estás seguro, este mini flujo casi siempre salva: 
git status
git branch --show-current
git diff
git log --oneline -n 5
